**提出**：2026-11-13　**状态**：已确认（2026-11-13）

> 来源：Henry 2026-11-13 的需求 prompt + 同日审核问答的 5 项决定。
> 标注「〔我定的〕」的条目是 prompt 和问答里都没有、由我补的默认值，审的时候请重点看这些。

## ① 要解决的问题

Henry 要在自己的 iPhone 上读 TXT 小说。没有 Mac，做不了原生 App，所以做成 PWA（Safari「添加到主屏幕」）。
书的来源是 iOS「文件」App（含 Google Drive 位置）里的 txt，编码不统一（UTF-8 / GBK / 少量 Big5），单本可能超过 20MB。
项目会长期迭代，按正式项目搭（git、CLAUDE.md、数据库迁移、每轮全量回归）。

## ② 最终用户动作

1. iPhone Safari 打开 GitHub Pages 地址 → 分享 →「添加到主屏幕」→ 从主屏幕图标打开（全屏，无 Safari 地址栏）
2. 书架页点「导入」→ 在「文件」App 里一次选多本 txt（含 Google Drive 位置）→ 书出现在书架上
3. 点一本书 → 进入阅读 → 点屏幕中间呼出菜单 → 打开目录 → 点某一章跳过去
4. 翻页模式：点右侧 1/3 或向左滑翻到下一页；翻到章末自动进下一章
5. 菜单 → 设置 → 改字号 / 行距 / 页边距 / 主题 / 阅读模式，立即生效
6. 直接划掉 App → 开飞行模式 → 重新打开 → 回到刚才那本书的原位置继续读
7. 书架 → 备份 → 导出 JSON 存到「文件」；换手机或数据丢了以后 → 从 JSON 恢复
8. 我发布新版本后，Henry 打开 App 看到「有新版本，点击刷新」→ 点一下 → 更新完成，书和进度都在

## ③ 这一版做什么

### 3.1 硬性约束（来自 prompt，不变）

- 原生 HTML / CSS / JS（ES modules），无框架、无构建、无 CDN，全部资源在仓库里
- GitHub Pages 托管，public 仓库，仓库名 `txt-reader`；仓库里只有代码，书的内容只在手机本地
- 只支持最新版 iOS Safari 的主屏幕 PWA 模式
- Service Worker 缓存 App 外壳；正文和进度存 IndexedDB；App 运行期间不发任何网络请求（Service Worker 检查更新除外）
- UI 文案中文
- 「不用 npm」只约束 App 本身。测试用的 Playwright 放在 `tests/` 下，有自己的 `package.json`，不参与 App 运行

### 3.2 功能清单

**书架**
- [ ] 列出已导入的书：书名（取文件名去掉 `.txt`）、进度 %（整数）
- [ ] 排序：按最近阅读时间倒序；从没读过的按导入时间倒序排在后面
- [ ] 删除书：弹确认框（页面内的弹层，不用浏览器原生 `confirm()`），确认后删除该书的正文、目录、进度
- [ ] 编码可疑的书（见「编码」）在书名旁显示「编码可能有误」

**导入**
- [ ] `<input type="file" multiple>`，不写 `accept`，选完后按扩展名检查，非 `.txt` 的文件列为失败「不是 txt 文件」（见文末变更记录 C2）；一次可选多本，逐本顺序处理，显示「正在导入 2/5：书名」
- [ ] 重复判断：文件名 + 文件大小（字节）都相同视为同一本 → 跳过并提示「《书名》已在书架」
- [ ] 一本失败不影响其他本，结束后汇总显示成功几本、跳过几本、失败几本及原因

**编码**
- [ ] 判断顺序：UTF-8 BOM → UTF-16LE BOM → UTF-16BE BOM → 无 BOM 时按 UTF-8 严格解码 → 失败则按 GBK 严格解码（浏览器的 `gbk` 实际是 GB18030，是 GBK 的超集）→ 仍失败则按 GBK 宽松解码，并把这本书标记为「编码可能有误」
- [ ] 不自动识别 Big5（决定 3 选 C）
- [ ] 书架上每本书的操作菜单里有「换编码重新导入」：选择编码（UTF-8 / GBK / Big5 / UTF-16LE / UTF-16BE）→ 重新选一次原文件 → 用指定编码解码并替换这本书的正文和目录，进度重置到开头
  - 〔我定的〕需要重新选文件，而不是在手机里保留一份原始字节。理由：保留原始字节会让每本书占两倍空间

**段落整理**（导入时做一次，存整理后的结果）
- [ ] 每行去掉首尾空白（含全角空格），丢弃空行；每个非空行算一个段落
- [ ] 显示时由 CSS 统一首行缩进两字

**分章**
- [ ] 标题行的判定，三条同时满足：
  1. 整理后的行以下列模式之一开头：`第` + 中文数字或阿拉伯数字 + `章/回/节/卷`；`Chapter` + 数字（不分大小写）；`序章`、`序言`、`楔子`、`引子`、`番外`、`后记`、`尾声`
  2. 整行不超过 30 个字
  3. 行尾不是 `。，；、：` 之一
- [ ] 第一个标题之前如果有正文，归为一章，标题叫「前言」
- [ ] 「卷」和「章」平铺成一级目录
- [ ] 全书没有任何标题时：按段落累加字数，累计达到 5000 字就在该段落结束处切一段，标题为「第 1 段」「第 2 段」…
- [ ] 识别出的单章超过 30000 字时：按同样的 5000 字规则再切，标题为「原标题 (1/7)」…；正好 30000 字不切
- [ ] 目录：列出所有章，高亮当前章（强调色 #D97757），点击跳到该章开头

**阅读（两种模式共用）**
- [ ] 任何时候 DOM 里只有当前一章的段落
- [ ] 菜单：顶部栏（返回书架、书名）、底部栏（目录、设置、当前章名和全书进度 %）
- [ ] 阅读页打开时保持屏幕常亮，离开阅读页或切到后台时释放

**滚动模式**
- [ ] 当前章上下滚动；章首有「上一章」按钮，章末有「下一章」按钮
- [ ] 点屏幕任意位置显示或隐藏菜单

**翻页模式**
- [ ] 用 CSS columns 把当前章排成横向多页
- [ ] 点左 1/3 上一页、右 1/3 下一页、中间 1/3 显示或隐藏菜单
- [ ] 手指左滑下一页、右滑上一页；翻页带横向滑动过渡〔我定的：约 200ms〕
- [ ] 章末再往后翻 → 下一章第一页；章首再往前翻 → 上一章最后一页
- [ ] 全书最后一页再往后翻 → 提示「已是最后一页」

**进度**
- [ ] 保存内容：第几章 + 章内第几个字（当前屏幕上第一个可见字在本章的序号）。不存页码或滚动像素
- [ ] 保存时机：翻页后、滚动停下 500ms 后、切到后台或关闭时
- [ ] 打开书时回到保存的位置；改字号、行距、页边距或切换阅读模式后，原来屏幕上第一个可见的字仍在当前屏幕内
- [ ] 进度 % = 向下取整（(当前章之前所有章的字数 + 章内序号) ÷ 全书字数 × 100）；到达最后一章的最后一页（或滚到底）记为 100%。字数不含标题行和换行

**设置**（全局保存，所有书通用）
- [ ] 阅读模式：滚动 / 翻页（默认翻页）
- [ ] 字号 14–30px，步长 1，默认 19〔我定的〕
- [ ] 行距 1.4–2.2，步长 0.1，默认 1.8〔我定的〕
- [ ] 页边距 8–40px，步长 4，默认 20〔我定的〕
- [ ] 主题：白天 / 护眼 / 夜间

**主题**
| 主题 | 背景 | 正文 |
|---|---|---|
| 白天 | #F2F1EC | #3A3A38〔我定的〕 |
| 护眼 | #F4ECD8〔我定的〕 | #4A4033〔我定的〕 |
| 夜间 | #1A1A1A〔我定的〕 | #8C8C8C〔我定的〕 |

UI 点缀色三个主题通用：主色 #5E8F8A、辅色 #738090、强调色 #D97757（进度条、当前章高亮）。

**备份与恢复**
- [ ] 导出 JSON：设置 + 每本书的元数据、目录、进度；勾选「包含正文」时再加上全部章节正文
- [ ] 勾选「包含正文」时先显示预计大小，超过 100MB 弹警告，由 Henry 决定是否继续
- [ ] 导出通过系统分享面板保存到「文件」
- [ ] 恢复（含正文的备份）：书、目录、进度、设置全部恢复
- [ ] 恢复（不含正文的备份）：恢复设置；每本书的进度先存为「待认领」，书架顶部显示「有 N 本书等待重新导入」和书名列表；之后导入的 txt 如果文件名 + 大小对得上，自动接回进度
- [ ] 〔我定的〕恢复时如果书架上已有同一本书（文件名 + 大小相同）：进度以备份为准，正文不动；备份里没有的书不受影响

**iOS 适配**
- [ ] 内容避开刘海和底部横条（safe-area）
- [ ] 禁止双击缩放和双指缩放
- [ ] `manifest.webmanifest`（`display: standalone`）、apple-touch-icon（180×180）
- [ ] 状态栏：`apple-mobile-web-app-status-bar-style` 设为 `black`（决定 4）

**更新机制**
- [ ] 版本号只在 `sw.js` 第一行的 `VERSION` 一处定义（见文末变更记录 C1），Service Worker 的缓存名为 `txt-reader-v<版本号>`
- [ ] 新版 Service Worker 安装完成后，App 内显示「有新版本，点击刷新」；点击后启用新版并刷新页面，旧缓存被删除
- [ ] 申请持久存储（`navigator.storage.persist()`）

### 3.3 数据模型（IndexedDB，库名 `txt-reader`，schema 版本 1）

| 仓库 | 主键 | 字段 |
|---|---|---|
| `books` | `id`（随机字符串） | `title`、`fileName`、`fileSize`、`encoding`、`encodingSuspect`（布尔）、`totalLen`（全书字数）、`chapterCount`、`addedAt`、`lastReadAt` |
| `tocs` | `bookId` | `entries`: 数组，每项 `{title, len}`（len = 该章字数） |
| `chapters` | `[bookId, idx]` | `text`（该章所有段落，用 `\n` 连接，不含标题行） |
| `progress` | `bookId` | `chapterIdx`、`offset`（章内第几个字）、`percent`、`updatedAt` |
| `settings` | `key`（固定为 `global`） | `mode`、`fontSize`、`lineHeight`、`margin`、`theme` |
| `pending` | `fileKey`（`文件名|字节数`） | 从不含正文的备份恢复出来、等待认领的 `progress` |

- 目录和正文分开存，书架页只读 `books`，打开书只读 `tocs` 的一条和 `chapters` 的一条
- 迁移：`db.js` 里维护一个按版本号排列的迁移函数数组，升级时从旧版本逐级执行到新版本；迁移只允许新增或转换，不允许清空已有仓库

**备份 JSON 格式**：`{ app: "txt-reader", backupVersion: 1, schemaVersion: 1, exportedAt, settings, books: [{ meta, toc, progress, chapters? }] }`

### 明确不做

- 云同步、账号、任何服务器端
- epub / pdf / mobi 等其他格式
- 在线书源、联网搜书
- 朗读（TTS）
- 书签、书内搜索、字体选择、进度拖动条、翻页动画样式选择（审核时列为以后迭代）
- Big5 自动识别；无 BOM 的 UTF-16 识别
- 滚动模式下跨章连续滚动（章末用「下一章」按钮）
- 两级目录（卷 → 章）
- 手动修正目录、自定义分章正则
- 书架封面、分组、搜索
- 横屏和 iPad 专门适配；Android 和桌面浏览器兼容
- 在手机里保留 txt 的原始字节
