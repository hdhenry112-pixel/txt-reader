## 发现的产品问题：页面关闭时最后一次位置会丢

- **现象**：滚动后不到半秒就刷新页面，重新打开书，回到的是「前言」。不只是章内位置没存上，连刚从目录跳到的那一章都没存上。
- **原因**：保存进度是往 IndexedDB 写，这个写入是异步的。页面关闭的瞬间，正在进行的写入被直接掐断。真机上「划掉 App」就是这种情况。
- **修法**：每次保存进度，先同步写一条到 `localStorage`（调用返回时已经落盘），再写数据库；数据库写成功后擦掉这条；App 启动时如果这条还在，就补进数据库。代码在 `js/storage/progress.js` 的「位置日志」部分，启动时的恢复在 `js/app.js`。
- **对 spec 的影响**：进度不再只存在 IndexedDB，登记为 spec ⑧ C3。
- **验证**：修复后那条测试通过；把「写日志」或「启动时恢复」任意一处删掉，测试都会变红。
- **仍不确定的**：真机上划掉 App 时，系统是否给页面留了执行这次同步写入的机会。这要看真机清单第 11 项。如果真机上不行，还有一层保底：滚动停下 500 毫秒后的自动保存，最多丢最后半秒的滚动。

## 首轮失败的 5 项：都是测试脚本的问题

第一次跑 M2 的测试，10 项里失败 5 项。逐个查下来，产品代码没有问题，是我的测试写法有问题：

| 失败的测试 | 原因 |
|---|---|
| 点正文显示菜单 | 测试用「点标题」来收起菜单，而菜单的顶部栏正好盖住了标题，点不到 |
| P4 滚到底显示 100% | 测试用「点标题」来呼出菜单，Playwright 点之前自动把标题滚回可见位置，等于把页面滚回了顶部 |
| 两条位置恢复 | 从目录跳章后，新的一章还没渲染出来，测试就开始滚动，滚的是旧的一章 |
| 断网后阅读 | 回到书架后列表是异步刷新的，测试立刻读了一次百分比，读到的是旧值 |

改法：点正文改成点屏幕固定坐标（和手指一样）；跳章后等新章标题出现；书架上的文字用会重试的断言。

后来又发现「书架排序」这条之前能过是碰巧：它也是回书架后立刻读列表。单独跑它 3 次，3 次都失败。改成会重试的断言。
顺带改了一处产品体验：回书架时先等列表刷新完再显示，不再先闪一下旧数据（`js/reader/reader.js` 的 `closeReader`）。

## 反向验证

用 `tests/mutate.mjs` 把代码改坏 9 处，每处单独跑：

| 改坏的地方 | 变红的测试 |
|---|---|
| 恢复位置时什么都不做 | 三条位置恢复 |
| 回书架时不保存 | P4、立刻回书架、立刻刷新 |
| 页面关闭时不保存 | 立刻刷新 |
| 进度计算把当前章也算进「之前」 | P2、P3、P4、去相关、章内位置（单元测试 5 项） |
| 保存进度时不更新最近阅读时间 | 书架排序 |
| 到书末不算 100% | P4 |
| 渲染时不清掉上一章 | 9 项 |
| 保存进度时不写位置日志 | 立刻刷新 |
| 启动时不恢复日志 | 立刻刷新、位置日志 |

9 处全部被抓到。前 7 处是在修位置日志之前做的，当时「立刻刷新」和「书架排序」本来就是红的，所以那几行里这两条变红不能算作证据；上表只列了能算证据的。

还原之后把 M2 的 12 项重复跑了 2 遍（24 次），全部通过，没有偶发失败。
