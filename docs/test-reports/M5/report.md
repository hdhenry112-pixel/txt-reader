## 过程中的问题

1. **App 的 bug：「读书中被锁 → 忘记图案」删除数据库失败。**
   K11 补充第一次跑，页面停在「删除失败：数据库被另一个页面占用」。原因是我把 IndexedDB 的 `blocked` 事件当成了失败。
   `blocked` 只表示还有连接没关完：刚调用 `close()` 的连接上如果还有事务在跑（这里是关书时保存进度的事务），close 会等它跑完，这期间删除请求收到 `blocked`，等连接关完会自己继续。
   改法：`blocked` 时继续等，10 秒还没删掉才报错。改后 K11、K11 补充各重复跑 3 次都过。
   删除失败时的处理本来就是对的：先删书、删成功再清 localStorage，所以失败时密码还在，不会出现「不画图案就能看到书」。

2. **测试脚本的问题（3 个，都不是 App 的问题）：**
   - K8 / K9 / K11 补充第一版用 F2 翻到第 3 页，失败。F2 第一章只有 2 页（`data-pages="2"`），第二次点击翻进了下一章。改用 F1 第 7 项（M4 用过的「第 3 页」）。
   - K11 补充第一版断言「忘记图案后 localStorage 完全为空」，失败。重新启动时 `loadSettings()` 会写回主题副本 `txt-reader:theme = day`，这是正常行为。改成断言只剩这一项。
   - 截图 04「图案不对」第一版没拍到提示文字：测试的 `failOnce` 在拍照前把提示清掉了。改成先拍照再清。

3. **界面问题：「更多」面板再次打开时停在上次滚到的位置。**
   看截图 10 时发现：面板加了手势密码一节后比 iPhone 15 的屏幕高，点过底部的「开启」后再打开，面板停在滚动后的位置，标题「更多」和导出一节看不到。
   改成每次打开都滚回顶上，K12 里加了断言 `scrollTop` 为 0。

4. **我自己的失误：** 改文档时用 shell 的 `node -e "..."` 写了含反引号的中文，bash 把反引号里的内容当命令执行了。命令全部失败，`git diff` 确认没有任何文件被改动。之后改用脚本文件。已写进 CLAUDE.md 第 ⑧ 节。

证据：
1. 同一个脚本去掉「切到后台 → 回来」两项，16 项全过。所以触发条件和这一来一回有关
2. 出问题时，页面已被 0.5.2 的 Service Worker 控制、缓存在、启动完成（`data-ready=1`）；手动给 Service Worker 发「问版本号」的消息，**立刻回复 0.5.2**；`navigator.serviceWorker.ready` 已经完成
3. 手动调用 `navigator.serviceWorker.register('sw.js')`：**10 秒后仍未完成**（既不成功也不报错）
4. `js/app.js` 的 `setupServiceWorker()` 先 `await register()`，再调 `showVersion()` 和挂「回到前台检查更新」。register 卡住，后面都不执行，所以版本号一直是「…」
5. 在本地测试服务器上复现了；**把 0.5.2 的遮挡代码去掉，照样复现**。所以和遮挡无关

不知道的：
- 精确的触发条件。单独做「回到前台 → 检查更新 → 断网 → 刷新」（等或不等更新请求完成）在本地和线上都不复现；完整的检查脚本（开启密码、刷新、解锁、模拟切到后台再回来、断网、刷新）才复现
- iPhone 上会不会遇到。电脑上的 WebKit 不等于 iPhone

影响：断网启动时底部版本号显示「…」，这次启动不会检查新版本。读书、锁屏、解锁不受影响（上表各项都过了）。

修法（Henry 回复「现在修」，在 0.5.3 修了，见下一节）：`showVersion()` 和挂更新检查不再等 `register()` 完成——`showVersion()` 本来只依赖 `navigator.serviceWorker.ready`，它在这种状态下是正常的。再加一条端到端测试，按上面复现的顺序断言断网后版本号出现。

## 过程中的问题

1. **部首字符（spec 没覆盖，已登记 C5）。** 第一个原型就看到 pdf.js 抽出的「一」是 U+2F00（康熙部首「一」），「气」「石」「雨」「水」同样。
   用 8 种字体各打印一行字再抽出来：「等线」和 Chromium 的默认字体会出部首字符，微软雅黑、宋体、黑体、楷体不会。这是字体自身的问题，真实中文 PDF 同样会遇到。
   不修的话，「第⼀章」认不出是标题（反向验证证实：G3、G4 变红）。
2. **我的第一版修正不完整。** 第一版用 NFKC，但它不认识部首补充区的大多数字：字体测试里「见」「长」抽出来是 U+2EC5、U+2ED3，NFKC 换不回来。
   改用 Unicode 官方的 EquivalentUnifiedIdeograph.txt（从 unicode.org 读取，只取两个部首区，共 328 个）。
3. **我的第二个错误：对照表生成器按下标两个两个取字。** 对照表里有 14 个目标字在扩展 B 区（占两个 UTF-16 单元），从第一个这样的字开始全部错位，「见」「长」查不到。抽查时发现，改成按码位取。
4. **文件写入工具把 `\u2E80` 这样的转义换成了字符本身**，源码里出现了难以辨认的部首字符范围。改成用 `String.fromCharCode(0x2E80)` 拼正则。
5. **pdf.js 的接口我记错了一处**：这个版本释放文档要用 `loadingTask.destroy()`，`doc.destroy` 不存在。原型一跑就报错，已改。
6. **pdf.js 标准版在 Node 里跑不了**，原型改在 WebKit 页面里跑（和 iPhone 上的情况一致）。
7. **测试脚本的问题**：单元测试第一版里，测试页的正文去掉数字后各页相同，被「重复的最后一行」规则当成页脚去掉了。是测试数据不现实，改成各页正文不同。
8. **M1 有 1 项测试红了**：期望的提示文字还是「不是 txt 文件」，spec 3.2 规定改成「不是 txt 或 pdf 文件」。只改了期望文字。
