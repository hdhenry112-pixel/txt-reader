# Spec: 1.0.1 —— 分章：认出带日期的长标题，不把「第X章完」当标题

**提出**：2026-11-15　**状态**：待确认

起因：Henry 2026-11-15 真机截图，一本网上连载合集（下称「JL.txt」，GBK，26420 行，不进仓库）的目录看起来是乱的。查下来有三个原因：

1. 章节顺序乱：**文件本身就这么排**（例：原文第 4450 行是第一百一十章，第 4591 行接着是第六章）。App 按文件顺序列目录，不改。
2. 36 行真正的标题没认出来：标题后面带发帖日期，超过 30 个字（例：第 23858 行「第二百二十六章美不胜收10／12／2004－10／16／2004」32 个字），这一章被并进上一章。
3. 47 行「第X章完」被当成了标题；另有同一个标题连写两行（一行不带日期、一行带日期），目录里出现 0 字或几十个字的项。

Henry 2026-11-15 决定：修 2、3，1 不处理。

---

## ① 要解决的问题

分章规则（`docs/spec-mvp.md` ③「分章」，代码 `js/chapterizer.js` 11–20 行）对网上连载整理的 txt 有两个漏洞：

- 标题行末尾的日期也算进 30 个字的上限，长一点的标题加上日期就超了
- 「第X章完」只要不超过 30 个字、以「第X章」开头，就被认成标题

## ② 最终用户动作

导入这类 txt → 打开目录 → 每一章是一项，没有「第X章完」，没有 0 字的重复项。

## ③ 这一版做什么

改 `js/chapterizer.js`，规则三条（R1–R3），其余分章规则不变：

**R1 结束语不是标题。** 整理后的行如果正好是 `第` + 数字 + `章/回/节/卷` + 可有空白 + `完`，到此结束，就不是标题，作为正文段落留在上一章末尾。
- 「第一百六十五章完」「第三章 完」→ 不是标题
- 「第三章完美」「第三章 完结」→ 照旧是标题（`完` 后面还有字）

**R2 行尾日期不计入 30 个字。** 判断「不超过 30 个字」时，先去掉行尾的日期再数。日期的写法：
- 单个日期：1–4 位数字 `/` 1–2 位数字 `/` 1–4 位数字；数字可以是半角或全角，斜杠可以是 `/` 或 `／`。例：`9／6／2003`、`８／２０／２００３`、`12/10/2003`
- 日期范围：两个日期中间用 `-`、`－`、`—`、`~`、`～`、`至` 连接，前后可有空白。例：`10／12／2004－10／16／2004`
- 日期前面可以有空白，也可以紧贴标题（例：`第一百八十一章FromRussiaWithLove1／17／2004`）
- 只去**行尾**的日期；日期在中间的照旧整行计数
- 目录里显示的标题**保持原样，带着日期**（见 ⑦ 第 1 条）

**R3 紧挨着的同一章标题合并。** 遇到一个标题行时，如果：
- 它的「第X章」部分（`第` + 数字 + `章/回/节/卷`，逐字比较）和当前这一章的标题相同，并且
- 当前这一章到这里为止的正文不到 200 个字

就不把它当新标题，而是作为正文段落放进当前这一章。目录里用前一个标题（见 ⑦ 第 2、3 条）。
- 「第一卷」后面紧跟「第一章」：`第一卷` 和 `第一章` 不同，照旧分成两项（spec-mvp ④ 里 0 字章合法的那条不受影响）
- 当前章正文已经有 200 字及以上：照旧分成两项（JL.txt 里「第二百一十六章 山雨欲来」就是这样，文件里这一章贴了两遍，各 6000 多字）

**明确不做**
- 不按章号重新排序目录（原因 1 是文件的问题）
- 文件里根本没有标题行的章（JL.txt 里第一百七十八、一百九十三、二百零五、二百零六、二百一十三章等，只有「第X章完」，没有开头的标题）照旧并在上一章里，不去猜
- 已经导入手机的书不会自动重新分章（见 ⑥）
- 不改数据库结构

## ④ 验收锚点

单元测试（`tests/unit/parse.test.mjs`），数据全部手写：

**R1**
| 输入 | `isTitle` |
|---|---|
| `第一百六十五章完` | false |
| `第三章 完` | false |
| `第三章完美` | true |
| `第三章 完结` | true |

`chapterize(['第一章 甲', 'x'×100, '第一章完', '第二章 乙', 'y'×50])` → 2 章：`第一章 甲` 104 字（100 + 「第一章完」4），`第二章 乙` 50 字。

**R2**（`字`×n 表示 n 个「字」）
| 输入 | 去掉日期后字数 | `isTitle` |
|---|---|---|
| `第一章` + `字`×27 + ` 10／12／2004－10／16／2004` | 30 | true |
| `第一章` + `字`×28 + ` 1/5/2004` | 31 | false |
| `第一章` + `字`×27 + `８／２０／２００３` | 30 | true |
| `第一章` + `字`×20 + ` 1/5/2004 ` + `字`×5 | 日期不在行尾，整行 38 | false |
| `第一章` + `字`×27 + ` 2004年1月5日` | 不认这种写法，整行 40 | false |

原有锚点不变：`第一章` + `字`×27 → true，`第一章` + `字`×28 → false。

**R3**
- `chapterize(['第五章 甲', '短', '第五章 甲 1/2/2004', 'x'×300, '第六章 乙', 'y'×100])` → 2 章：`第五章 甲` 315 字（1 + 「第五章 甲 1/2/2004」14 + 300），`第六章 乙` 100 字
- 边界：前一章正文 199 字 → 合并（1 章）；正好 200 字 → 不合并（2 章）
- `chapterize(['第一卷', '第一章 x', 'z'×10])` → 2 章，`第一卷` 0 字（和现在一样）

**真实文件（本地检查，不进仓库）**：JL.txt 按新规则分章
- 目录 249 项 → 222 项（2026-11-15 用草稿脚本试算）
- 没有一项的标题是「第X章完」
- 不到 200 字的项 0 个（试算里最短的是「第二百一十七章估计重施」773 字）
- 第二百二十四、二百二十六、二百二十七、二百二十八章各出现一次
- 超过 12000 字的项 7 个，都是文件里缺标题行造成的（明确不做的那条）

## ⑥ 对已导入的书的影响

目录是导入时算好存进数据库的，升级到 1.0.1 后已有的书不变。要让 JL 用新目录，两种办法，**阅读进度都会回到开头**：
- 书架上这本书的「⋯」→ 删除 → 重新导入
- 「⋯」→ 换编码重新导入（选 GBK）

新目录的章数变了，旧进度里的「第几章」对不上，所以没办法保留。重新导入前记一下读到第几章。
