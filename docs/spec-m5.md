## ① 要解决的问题

1. **手势密码**：现在任何人拿到解锁的手机，点开 App 就能看到书架。Henry 要在进书架之前先画一个九宫格图案。
2. **PDF**：Henry 有一部分小说是 PDF 格式（文字型，能选中文字），现在只能导入 txt。

## ② 最终用户动作

**手势密码**
1. 书架 →「更多」→ 手势密码 → 开启 → 画一个图案 → 再画一次确认
2. 划掉 App → 重新打开 → 出现九宫格 → 画对 → 进入书架
3. 读书时切到别的 App，过了 5 分钟以上再切回来 → 出现九宫格 → 画对 → 回到刚才读的那一页
4. 忘了图案 → 点「忘记图案」→ 确认 → 全部数据清空，回到空书架，没有密码

**PDF**
1. 书架 →「导入」→ 选一个 PDF（可以和 txt 一起多选）→ 书出现在书架上
2. 点开 → 和 txt 的书一样：有目录、能翻页、能调字号和主题、进度自动保存
3. 飞行模式下也能导入 PDF

### 3.1 手势密码（M5a）

**图案规则**
- [ ] 3×3 共 9 个点，编号从左到右、从上到下为 0–8
- [ ] 手指按下并拖过各点，松手即提交。一个点只能连一次
- [ ] 至少连 4 个点；不足 4 个提示「至少连 4 个点」，不算一次错误尝试
- [ ] 〔我定的〕从一个点直线划到另一个点，中间正好经过一个还没连过的点时，那个点自动连上（和安卓锁屏一样）。例：从 0 直接划到 2，记为 0-1-2

**开启、修改、关闭**
- [ ] 入口：书架右上角的「备份」按钮改名为「更多」，面板里在备份、恢复之外加一节「手势密码」〔我定的〕
- [ ] 开启：画一次 → 再画一次，两次相同才生效；不同则提示「两次不一致」，回到第一步
- [ ] 修改、关闭：都要先画对当前的图案
- [ ] 默认关闭。没开启时 App 的行为和 0.4.1 完全一样

**什么时候要画**
- [ ] App 启动时（包括划掉后重开、刷新）
- [ ] 从后台回到前台，且离开前台的时间 **≥ 5 分钟**（300 秒）。不到 5 分钟不用画
- [ ] 锁屏页出现时，书架和阅读页的内容不可见、不可操作
- [ ] 画对之后回到锁之前的页面；如果当时在读书，回到原来那一页

**画错**
- [ ] 画错提示「图案不对」，可以马上再画
- [ ] 〔我定的〕连续画错 5 次 → 30 秒内不能再画，页面显示剩余秒数；30 秒后可以再画，再错一次又是 30 秒；画对后错误次数清零
- [ ] 等待期间划掉 App 重开，等待仍然有效（错误次数和解禁时间存下来）

**忘记图案**（决定 1 选 A）
- [ ] 锁屏页有「忘记图案」→ 页面内确认框，写明「会删除手机里所有的书、阅读进度和设置，不能恢复」→ 确认后清空 IndexedDB 和 localStorage，回到空书架，没有密码
- [ ] 没有任何别的找回办法

**存储**
- [ ] 〔我定的〕存在 `localStorage`（键 `txt-reader:lock`），不进 IndexedDB，不改 schema。原因：启动第一帧之前就要知道有没有锁，读 IndexedDB 是异步的
- [ ] 存的是加盐的摘要（`crypto.subtle` 的 PBKDF2），不存图案本身
- [ ] 备份文件里不包含手势密码；恢复备份不改变当前的手势密码

**能防什么、不能防什么**（决定 3：Henry 确认只要这个程度）
- 能防：别人拿到解锁的手机，随手点开 App 看书架
- 不能防：书的正文在手机里不加密；合法图案总共只有几十万种，懂技术的人拿到存储数据可以穷举出来。这一版不做正文加密

### 3.2 PDF 导入（M5b）

**做法**（决定 4：文字型小说）
- [ ] 导入时用 pdf.js 把每一页的文字抽出来，整理成段落，交给现有的分章流程，存成和 txt 完全一样的书
- [ ] 之后的阅读、目录、进度、设置、备份、恢复都走现有代码，不区分来源
- [ ] 〔我定的〕PDF 原文件不保存在手机里，只保存抽出来的文字（和 txt 一样）
- [ ] 书的元数据加一个字段 `source`：`'txt'` 或 `'pdf'`。旧书没有这个字段，按 `'txt'` 处理，**不需要数据库迁移**
- [ ] PDF 来的书，「更多操作」里不显示「换编码重新导入」

**文字整理规则**
- [ ] 同一页里纵坐标接近的文字片段合成一行，行内按横坐标从左到右
- [ ] 去掉页眉页脚：某一页的第一行或最后一行，如果（把数字都换成 `#` 之后）在 **一半以上的页** 里都出现在同样的位置，就丢弃；最后一行如果只有页码（如 `12`、`- 12 -`、`第 12 页`、`12 / 300`）也丢弃。全书不足 5 页时不做「重复行」判断，只去页码
- [ ] 分段：一行算新段落的开头，当它满足任意一条——① 行首比正文左边界缩进至少 1 个字宽；② 上一行的右端比正文右边界短至少 2 个字宽；③ 这一行按现有规则是章节标题，或上一行是章节标题。否则接在上一行后面
- [ ] 换页不强制分段（一段可以跨页）
- [ ] 两行相接：前一行末尾和后一行开头都是英文字母或数字时中间加一个空格，否则直接相连
- [ ] 分章：整理出段落后用现有的 `chapterize`，规则不变。**不读 PDF 自带的书签**〔我定的；待确认项 2〕

**导入流程**
- [ ] 文件选择框仍然不写 `accept`。扩展名是 `.txt` 走原流程，`.pdf` 走 PDF 流程，其他的列为失败「不是 txt 或 pdf 文件」
- [ ] 重复判断、等待重新导入的认领：和 txt 一样，按「文件名 + 字节数」
- [ ] 进度提示：「正在导入 1/2：书名（第 35 / 300 页）」
- [ ] 失败原因写清楚：
  - 抽不出文字 →「这个 PDF 里没有可提取的文字（可能是扫描版）」
  - 有密码 →「这个 PDF 有密码保护」
  - 文件损坏或不是 PDF →「不是有效的 PDF 文件」
- [ ] 一本失败不影响其他本

**第三方代码**（Henry 2026-11-14 已同意）
- [ ] pdf.js（Mozilla，Apache-2.0）的文件拷进仓库的 `vendor/pdfjs/`，连同它的 LICENSE 和一个写明版本号、来源地址、各文件 sha256 的 `VERSION.md`
- [ ] 不用 CDN、不用 npm 构建。App 只在导入 PDF 时才动态加载它，不影响启动速度
- [ ] 所有文件进 `sw.js` 的缓存清单，保证离线可用
- [ ] 中文 PDF 需要的字符映射表（cmaps）一并放入
- [ ] **不许改 pdf.js 的源码**。校验用 sha256，不用字符数或子串

### 明确不做

- 扫描版 PDF、OCR、把 PDF 页面当图片显示、双指缩放
- PDF 里的图片、表格、原版式、多栏排版、竖排、脚注处理
- 读 PDF 自带的书签当目录（待确认项 2）
- 在手机里保存 PDF 原文件
- 正文加密；用 Face ID / Touch ID 解锁；用数字密码代替或找回图案
- 每本书单独上锁
- epub、mobi 等其他格式

## ⑧ 已知风险

1. **pdf.js 的具体版本、需要哪些文件、总共多大，写 spec 的时候没有核实。** 开工第一件事是查 pdf.js 的官方文档确定这些，把实际大小告诉 Henry（之前口头估的是 2–4MB）。
2. **pdf.js 在 iPhone Safari 上的内存和速度没有把握。** 抽文字要逐页处理、处理完一页就释放，不能把整本书的页面对象都留在内存里。
3. **分段和去页眉的规则是启发式的**，真实 PDF 的排版千差万别，肯定有处理不好的。遇到了让 Henry 把那本书的现象发来，调规则并加锚点。
4. **用 Chromium 打印生成测试 PDF 这条路没试过。** 生成出来的 PDF 的文字片段切分方式可能和真实小说 PDF 不同，测试通过不代表真书没问题。
5. **多任务界面的缩略图**可能在 App 来得及盖上锁屏页之前就截好了。这一点只能真机看，可能做不到完全不露。
6. **localStorage 被系统清掉时密码会消失**（书在 IndexedDB 里可能还在）。一般两者是一起清的，但我证明不了。
7. **合法的图案总数有限**，摘要可以被穷举。这是已知并接受的（见 3.1 末尾）。
